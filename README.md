# MR603 — Backlog Prioritisation RL Project — Local Setup Guide

Two ways to run this locally: **Jupyter Notebook** (recommended if you already
have it — see `Week8_Local_Run.ipynb`) or the **terminal** (steps below work
either way, just skip Step 6 if using the notebook).

## If you're using Jupyter Notebook

1. Complete Steps 1, 3, 4, and 5 below (Python installed, project unzipped,
   virtual environment created and activated, packages installed).
2. Launch Jupyter **from inside your activated virtual environment**:
   ```
   jupyter notebook
   ```
3. Open `Week8_Local_Run.ipynb`.
4. Click **Kernel > Restart Kernel and Run All Cells** (or run each cell one
   at a time with `Shift+Enter`) so the output is generated by *your* run,
   not a pre-baked example.
5. Screenshot each cell's output as you go — that's your evidence.

The notebook already comes with example output saved in it (from a
verification run) so you can see what to expect — but re-running it yourself
replaces that with your own genuine local execution.

---

## Step 1 — Install Python

You need Python 3.10 or newer (this was built and tested on 3.12).

- **Windows/Mac:** download from https://www.python.org/downloads/ and install.
  During install on Windows, tick **"Add Python to PATH"**.
- **Check it worked** — open a terminal (Command Prompt / PowerShell / Terminal)
  and run:
  ```
  python --version
  ```
  You should see something like `Python 3.12.3`. (On Mac/Linux you may need
  `python3 --version` instead.)

## Step 2 — Install an editor (recommended, not required)

**VS Code** is the easiest for beginners: https://code.visualstudio.com/
After installing, also install the "Python" extension from the Extensions
tab inside VS Code (the icon on the left sidebar that looks like squares).

## Step 3 — Unzip the project

1. Download `Bhimarjun_Week8_Code.zip` (already provided).
2. Unzip it into a folder — e.g. `Documents/MR603-Thesis/`.
3. Open that folder in VS Code (`File > Open Folder`), or navigate to it
   in your terminal:
   ```
   cd path/to/Documents/MR603-Thesis
   ```

## Step 4 — Create a virtual environment (keeps this project's packages separate)

In the terminal, inside the project folder:

```
python -m venv venv
```

Then activate it:

- **Windows:** `venv\Scripts\activate`
- **Mac/Linux:** `source venv/bin/activate`

You'll know it worked because your terminal prompt will now show `(venv)`
at the start of the line.

## Step 5 — Install the required packages

Still in the terminal, with `(venv)` active:

```
pip install -r requirements.txt
```

This installs numpy, gymnasium, and matplotlib — the only three external
packages this project needs.

## Step 6 — Run the code yourself

Each of these should print real output to your terminal, exactly like the
evidence document showed — except now it's happening on your machine:

```
python -m backlog_rl.env.generator
python -m backlog_rl.baselines.static_scorers
python -m unittest backlog_rl.tests.test_static_scorers -v
python -m backlog_rl.env.backlog_env
python -m backlog_rl.baselines.run_comparison
python -m backlog_rl.explain.template_explainer
```

The `run_comparison` command will also save a chart called
`baseline_comparison.png` in your project folder — open it to see the
RICE/WSJF/Random comparison, generated locally by you.

## Step 7 — Take your own screenshots

Once everything runs, take screenshots of:
- Your terminal showing the unit tests passing
- Your terminal showing the baseline comparison numbers
- The generated chart image
- VS Code (or your editor) with the project folder open, showing the file
  structure — this alone is strong visual evidence of a real local setup

## Step 8 — Set up Git (strongly recommended before Monday)

This gives you commit history — evidence of incremental work over time,
which supervisors specifically look for.

1. Install Git: https://git-scm.com/downloads
2. In your project folder terminal:

3. (Optional but recommended) Create a free GitHub account and push this
   repository there, so you have a shareable link and cloud backup.

## Troubleshooting

- **"python: command not found"** → Python isn't on your PATH. Reinstall
  and make sure to tick the PATH checkbox, or use `python3` instead of
  `python`.
- **"pip: command not found"** → Try `python -m pip install -r requirements.txt`
  instead.
- **Import errors when running scripts** → make sure you're running the
  commands from the top-level project folder (the one containing the
  `backlog_rl` folder), not from inside `backlog_rl` itself.
